```powershell
# v0.5
$taskNode = 'C:\Users\{用户名}\.cache\codex-runtimes\...'  # 硬编码示例
```

```javascript
// v0.5
if (/HTTP (401|402)/.test(error.message)) { stopAPI = true; }

if (isFatalAccountError(error)) { stopAPI = true; }
```

### 日志输出
```javascript
// v0.5
console.log('搜索：' + query);

// v0.6
logger.debug(`搜索：${query}`);  // 可控制级别
```

### 配置管理
```javascript
// v0.5
if (canonical(c.quote).length < 4) { ... }  // 魔法数字

// v0.6
if (canonical(c.quote).length < VALIDATION.MIN_QUOTE_LENGTH) { ... }
```

## 🎓 技术亮点

### 1. 自动路径检测
```powershell
function Find-NodeExecutable {
    $searchPaths = @(
        "$env:USERPROFILE\.cache\codex-runtimes\...",
        'C:\Program Files\nodejs\node.exe',
        'C:\Program Files (x86)\nodejs\node.exe'
    )
    # 还会尝试PATH和NODE_PATH环境变量
}
```

### 2. 错误码标准化
```javascript
export const ERROR_CODE = {
  ACCOUNT_UNAUTHORIZED: 'ACCOUNT_401',
  ACCOUNT_PAYMENT_REQUIRED: 'ACCOUNT_402',
  RATE_LIMIT: 'RATE_LIMIT_429',
  CONTENT_CAPTCHA: 'CONTENT_CAPTCHA',
  ROBOTS_DISALLOWED: 'ROBOTS_DISALLOWED',
  // ... 完整枚举
};
```

### 3. robots.txt检查
```javascript
// 自动解析和缓存
const robotsCheck = await checkRobotsPermission(url);
if (!robotsCheck.allowed) {
  throw new UnderwritingError(
    ERROR_CODE.ROBOTS_DISALLOWED,
    robotsCheck.reason
  );
}
```

### 4. 分级日志
```javascript
logger.setLevel('DEBUG');  // 通过代码或环境变量设置

logger.error('严重错误');   // 总是显示
logger.warn('警告信息');    // WARN及以上显示
logger.info('一般信息');    // INFO及以上显示（默认）
logger.debug('调试信息');   // 仅DEBUG级别显示
```

### 5. 配置常量化
```javascript
// 所有常量统一管理
export const VALIDATION = {
  MIN_QUOTE_LENGTH: 4,
  MIN_TEXT_LENGTH: 100,
  MAX_PAGE_SIZE: 1500000,
  // ...
};

export const HTTP = {
  DEFAULT_TIMEOUT: 90000,
  USER_AGENT: 'UnderwritingResearch/0.6',
  // ...
};
```

## 📞 技术支持

### 常见问题

**Q: v0.6可以和v0.5并存吗？**  
A: 可以。它们使用不同的cmd入口，互不干扰。

**Q: 需要重新配置密钥吗？**  
A: 不需要。v0.6会自动使用v0.5或v0.4的密钥。

**Q: 缓存可以共享吗？**  
A: 可以。两版本缓存结构相同，可以安全共享。

**Q: 如何回退到v0.5？**  
A: 直接运行`运行核保_DeepSeek_v0.5.cmd`即可。

**Q: v0.6会影响业务逻辑吗？**  
A: 不会。核心业务逻辑完全相同，仅代码组织改进。
